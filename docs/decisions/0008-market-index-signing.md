# ADR-0008：插件索引审核与签名

- 状态：已接受
- 日期：2026-11-24
- 责任人：项目维护者
- 关联：[ADR-0007](0007-third-party-distribution.md)、[插件索引 v1](../plugin-index-v1.md)

## 背景

阶段 E 引入插件市场。索引仓库如果只依赖 GitHub 仓库写权限，一次误合并或被篡改的 PR 就可能让 App 接受未审核条目；需要把“谁批准上架”和“App 接受什么”分成两层。

## 决策

1. 第三方插件上架必须通过索引仓库的 PR 审核；CI 校验结构、哈希、签名者连续性与 APK 元数据，但不自动合并。
2. `registry.json` 通过后由受保护工作流签名，生成 `registry.sig`：
   - 算法 ECDSA P-256 + SHA-256；
   - 载荷为 `lifehub-index-v1\n<registry.json SHA-256>`；
   - 私钥只存放在 GitHub Environment `index-signing` 的 Secret；
   - 公钥提交在 `keys/<keyId>.pem`，并内置到 App 的 `assets/market/keys/`。
3. App 拉取索引后先验签，只接受签名有效的网络或缓存索引；失败时回退到上一份有效缓存或内置快照。
4. 索引只作发现，不作为信任根；安装前仍校验包结构、SHA-256、签名者连续性、版本不降级与能力声明。
5. 密钥轮换：先发布内置新公钥的 App，再切换索引签名工作流的 `keyId`；旧密钥保留在 App 中直到新版本覆盖率足够。
6. 第一方 memo 插件由独立 Release 工作流发布；索引扫描只负责生成 PR，不自动合并或签名。

## 理由

- PR 审核保留了人工判断与审计记录；索引签名保证即使仓库被改写，App 也不会接受未签名条目。
- 复用现有 ECDSA P-256 校验能力，不引入新依赖。
- 把自动扫描、人工合并、签名审批拆开，降低单点失误的影响。

## 后果

- 需要维护索引签名密钥与环境审批配置；私钥丢失或泄露时必须走轮换流程。
- 索引更新到上架之间多一次人工合并与签名步骤。
- 索引仓库的写权限不再等于上架权限，但仍需保护 PR 审核与 Environment 审批权限。
- 商店渠道若限制远程插件分发，仍按 ADR-0007 退回侧载或仅保留内置插件。
