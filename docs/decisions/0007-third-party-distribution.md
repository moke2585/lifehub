# ADR-0007：第三方插件分发与合规边界

- 状态：已接受（待发行负责人复核）
- 日期：2026-11-23
- 责任人：项目维护者；提审前需发行负责人签字
- 部分替代：[ADR-0002](0002-distribution-and-compliance.md)

## 背景

ADR-0002 为保护首版，明确不实现插件市场、远程插件下载和第三方代码分发。现在产品决定引入插件市场与离线安装，需要重新定义分发渠道、信任层级和商店合规边界。

本记录不是法律意见；正式提审前必须按当期 Google Play 政策重新核对并由发行负责人签字。

## 决策

1. 支持三种插件来源：
   - `BUILT_IN`：随宿主 APK 发布的第一方模块。
   - `EXTERNAL_ZIP`：用户从 GitHub Release 下载或本地导入的 `.lhplugin` 声明式包。
   - `EXTERNAL_APK`：用户从 GitHub Release 下载或本地导入的独立插件 APK。
2. 插件索引位于独立 `lifehub-plugins` 仓库，App 只把它当可缓存元数据，不作为信任根。
3. 离线安装必须可用：
   - ZIP 通过 SAF 导入，无需系统安装权限。
   - APK 通过 `PackageInstaller` 或系统安装器，用户必须明确确认；如使用 App 内安装，需声明 `REQUEST_INSTALL_PACKAGES`。
4. 安装前必须向用户展示：
   - 插件名称、版本、来源、签名者、能力清单；
   - 在线/离线来源；
   - ZIP 为“无代码声明式插件”，APK 为“独立代码插件”。
5. 信任分层：
   - 官方/第一方：内置或官方签名。
   - 已验证第三方：注册表登记签名者指纹。
   - 本地未验证：允许导入，但必须显示风险提示，默认不自动启用。
6. 合规边界：
   - 不实现宿主内动态代码加载。
   - ZIP v1 不包含可执行代码；如后续引入 WASM/脚本，必须新增 ADR 并重新做政策审查。
   - APK 插件是独立应用，不是宿主内动态加载；仍需评估商店对插件市场和第三方代码分发的政策。
   - 网络能力仅用于索引刷新和下载；插件网络能力单独声明与授权。
7. 数据安全与隐私文档必须更新：
   - 说明索引请求、下载来源、签名校验和离线导入；
   - 说明 APK 插件的数据由插件自己持有，宿主备份依赖插件导出接口。

## 理由

- 插件市场是产品方向，继续用 ADR-0002 的一刀切禁止会阻碍实现。
- 离线安装和签名校验可以在不引入远程代码执行的前提下开放生态。
- 把 ZIP 与 APK 的信任与数据边界写清楚，避免“插件市场”变成无约束的代码分发通道。

## 后果

- 需要更新隐私政策、Data safety、发布检查表与商店提审材料。
- 远程索引/下载可能需要网络权限；首版“无网络”承诺被扩展，需要重新表述。
- 第三方 APK 的能力无法由宿主 broker 强制约束，必须以 Android 沙箱和安装时告知为主要边界。
- 若商店政策不允许相关分发方式，需要退回侧载/私有分发，或只保留内置与 ZIP。

## 变更方式

由发行负责人发起新 ADR，附当期政策链接、审查日期与结论；在完成前不得把市场入口提交到受限渠道。
