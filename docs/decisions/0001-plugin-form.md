# ADR-0001：首版插件形态

- 状态：已接受（已被 ADR-0006 部分替代：外部 ZIP/APK 安装形态）
- 日期：2026-11-11
- 责任人：项目维护者

## 背景

`design.md` 列出三种插件形态：dex/APK 动态加载、JS/小程序式、混合式。`plan.md` 允许在不需要验证脚本执行边界时，首版先验证插件 API、页面 schema、生命周期与数据隔离，把通用脚本 runtime 延后。

首版只有随 APK 发布的第一方插件（记账、备忘录），没有第三方作者，也没有不发版更新插件逻辑的需求。

## 决策

1. 插件包是 APK `assets` 内内置的版本化 ZIP：`manifest.json`、`pages/*.json`、静态资源、action 声明；**不包含 dex、native 库或 JavaScript**。
2. 宿主用 Compose 渲染声明式页面 schema；交互 action 由随 APK 编译的第一方 Kotlin `PluginActionHandler` 实现，经宿主 broker 访问插件私有数据。
3. 不引入 JS 引擎，不动态加载可执行代码，不做插件自更新。
4. action 在 `plugin-api` 中以稳定 id 契约暴露。未来若引入 QuickJS，可把 action 实现替换为独立进程 runtime，页面 schema 与插件包格式保持不变。

## 备选方案对比

| 方案 | 首版成本 | 隔离与稳定性 | 商店风险 | 结论 |
|---|---|---|---|---|
| APK 内置声明式插件包 + 第一方 Kotlin action | 低：无 native、无 IPC | 插件代码随 APK 发布，崩溃等同宿主崩溃 | 低：无远程代码 | **采用** |
| 声明式插件包 + QuickJS 独立进程 | 高：arm64 native 构建、IPC 协议、执行预算、故障注入 | 进程隔离最好 | 中：解释执行需按渠道政策复核 | 延后，见触发条件 |
| Dex/APK 动态加载 | 高：插件框架、兼容与签名体系 | 差：无天然沙箱 | 高：Play 禁止此类代码分发 | 不采用 |

## 理由

- 首版要验证的是插件契约、页面 schema、生命周期和数据隔离，这些与 action 用什么语言实现无关。
- 不引入 native 依赖，构建、测试和 arm64 兼容风险显著降低；JVM 单元测试即可覆盖大部分逻辑。
- 不为尚不存在的第三方插件提前承担脚本攻击面与商店合规审查成本。

## 后果

- `plan.md` P4 的独立进程 runtime 延后；首版崩溃隔离仅依赖宿主质量与 P7 的连续崩溃护栏。由于 action 代码随 APK 发布，该风险与普通应用内部模块相同。
- 远程插件、第三方插件、插件热更新在补齐新 ADR 前不可实现。
- P8 的 dev-harness 仍可加载本地插件包，因为包格式与宿主一致。

## 未完成事项

未构建 QuickJS 最小原型。`plan.md` 允许在该路线不进入首版时延后；若出现以下任一触发条件，必须先补做 arm64 QuickJS 原型、IPC 威胁模型与新 ADR，再改实现：

- 需要第三方作者在不发布宿主新版本的情况下上架插件；
- 需要远程更新插件逻辑；
- 需要脚本化 action 或插件市场。

## 变更方式

新增 ADR 替代本记录，并同步更新 `plugin-api` 兼容策略、`scope-freeze.md` 与 P4 范围；不得在实现中静默引入脚本引擎或动态代码加载。
