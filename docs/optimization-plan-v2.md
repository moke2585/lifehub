# 优化计划 v2：主页小组件与交互升级

- 状态：阶段 1–3 与全局 Quick Find 已实现并通过三星平板横屏真机回归（2026-11-13）
- 日期：2026-11-13
- 依据：[实施计划](../plan.md)（P0–P9 已完成）、交互设计调研结论、主页归属讨论
- 范围：`:app` 宿主、任务清单插件、记账插件、`:plugin-api`、`:dev-harness`
- 核心原则：**微内核 + 插件贡献点**。插件贡献内容，宿主提供舞台。

## 1. 背景与目标

### 1.1 当前基线

已完成的能力不再重复建设：

- 声明式插件页面、manifest 校验、能力授权、私有存储、备份与迁移。
- 任务清单：截止日期、1–5 优先级、Emoji、紧急指数、紧急/最近排序、滑动完成/删除、30 天回收站、日常任务倍率、筛选、搜索、大卡片。
- 记账：增删改查、日/月/年统计、柱状图、环图、左滑删除、撤销。
- 交互基线：可逆操作立即执行 + Snackbar 撤销；编辑页自动聚焦；列表空态主按钮；顶栏动作；主页已启用插件“+”快捷新建。

### 1.2 本轮目标

1. 主页从“插件列表”升级为“插件组合面”：插件通过 manifest 贡献小组件，宿主通用渲染，新增插件不需要改主页业务代码。
2. 打通高频闭环：任务“今天 → 快速添加 → 完成/撤销”；记账“打开 → 记一笔 → 再记一笔/搜索”。
3. 增加主页个性化：置顶、最近使用、小组件显示与排序。
4. 保持现有安全边界：插件不注入任意 UI，不绕过能力授权，不直接访问数据库。

### 1.3 成功指标

| 指标 | 目标 |
|---|---|
| 新插件接入主页 | 0 处宿主 `when (pluginId)` 业务分支；只需 manifest + data handler |
| 任务快速添加 | 输入后 ≤ 2 次点击完成 |
| 常见记账 | 金额 → 分类 → 保存 ≤ 3 步 |
| 可逆操作 | 100% 提供撤销 |
| 空状态 | 100% 提供一个主行动 |
| 主页首屏 | 小组件不阻塞首帧；有骨架、超时和失败回退 |
| 主页密度 | 默认最多 3 个小组件，总数上限 6 个 |

## 2. 设计原则与边界

### 2.1 四层归属

| 层 | 归属 | 例子 |
|---|---|---|
| 主页壳 | 宿主 | 布局、分组、置顶、最近使用、编辑模式、加载/错误/空态、主题 |
| 插件小组件 | 插件声明，宿主渲染 | 今日任务、本月支出、预算进度、最近记录 |
| 插件入口 | 插件声明，宿主渲染 | 打开插件、快捷新建“+/记一笔” |
| 插件页面 | 插件 | 编辑表单、筛选、统计详情、回收站 |

判断规则：

```text
新增主页内容
├─ 与具体插件数据无关（排序/置顶/搜索/布局/快捷方式） → 宿主主页
├─ 展示某个插件的数据（任务数/支出/预算/最近记录） → 插件小组件
├─ 只是打开插件或新建一条记录 → manifest 的 entryPage / quickCreate
└─ 需要表单、筛选、长列表、多步操作 → 插件页面
```

### 2.2 插件贡献点

“一切皆插件”指所有业务能力通过统一契约接入，不指插件拥有任意 UI：

| 贡献点 | 插件提供 | 宿主提供 |
|---|---|---|
| `pages` | 页面 JSON | 校验、渲染、导航 |
| `actions` | action handler | 分发、权限、确认/撤销 |
| `dataHandlers` | 数据语义 | 能力代理、限额、错误处理 |
| `quickCreate` | 入口页面与文案 | 主页“+”与长按快捷方式 |
| `homeWidgets` | 小组件描述与数据源 | 模板渲染、布局、刷新、个性化 |

### 2.3 非目标（v1）

- 不做第三方 APK 的小组件；当前 data handler 仍是宿主注册的 Kotlin 代码。
- 不做插件自定义 Compose/HTML/动态代码。
- 不做主页整体插件化；主页组合引擎属于宿主内核。
- 不做 `chart` 小组件、桌面小组件、后台轮询；留到后续阶段。
- 不把小组件做成迷你页面：不支持表单、嵌套滚动、长列表。

## 3. 目标架构

### 3.1 主页信息架构

```text
主页
├─ 今日小组件区（默认最多 3 个，可编辑）
│   ├─ 今日任务（任务清单贡献）
│   ├─ 本月支出（记账贡献）
│   └─ 其他已启用插件的小组件
├─ 已启用插件卡片（打开 / + 快捷新建 / 更多）
├─ 待处理插件
└─ 可用插件
```

不新增“小组件”Tab；底部导航保持“主页 + 独立插件页”，不超过 Material 3 建议的 5 个目的地。

### 3.2 Manifest 契约

在 `PluginManifest` 增加可选字段：

```json
{
  "homeWidgets": [
    {
      "id": "today_tasks",
      "type": "summary",
      "title": "今日任务",
      "size": "small",
      "priority": 100,
      "sourceId": "memo_summary",
      "params": { "filter": "today" },
      "action": {
        "type": "navigate",
        "pageId": "list",
        "params": { "filter": "today" }
      },
      "sensitive": false
    },
    {
      "id": "month_spend",
      "type": "summary",
      "title": "本月支出",
      "size": "small",
      "priority": 90,
      "sourceId": "ledger_summary",
      "params": { "period": "month" },
      "action": {
        "type": "navigate",
        "pageId": "list",
        "params": { "period": "month" }
      },
      "sensitive": true
    }
  ]
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 插件内唯一；用户偏好按 `pluginId + id` 保存 |
| `type` | 是 | v1 支持 `summary`、`progress`、`list`、`quick_actions`；未知类型运行时忽略 |
| `title` | 是 | 小组件标题，≤ 20 字符 |
| `size` | 否 | `small`（1 列）、`medium`（2 列）、`large`（通栏），默认 `small` |
| `priority` | 否 | 0–100，仅用于默认排序；用户排序优先 |
| `sourceId` | 数据类必填 | 复用 `PluginPageDataHandler` 注册的 sourceId |
| `params` | 否 | 传给数据源的参数，例如 `filter=today`、`period=month` |
| `action` | 否 | 点击整个小组件的动作；v1 只允许 `navigate` |
| `sensitive` | 否 | 金额/隐私数据；宿主提供“隐藏金额”开关 |
| `maxItems` | 否 | `list` 类型最多显示条数，默认 3，上限 5 |
| `refresh` | 否 | v1 仅支持 `on_resume`；后续可扩展 |

### 3.3 v1 模板

| type | 展示 | 数据映射 | 交互 |
|---|---|---|---|
| `summary` | 标题 + 主数字 + 辅助说明 | `PluginDataResult.metrics[0]`，`metrics[1]` 作为说明 | 点击打开 `action` |
| `progress` | 标题 + 数值 + 进度条 | `metrics[0].value` 与 `metrics[0].ratio` | 点击打开 `action` |
| `list` | 标题 + 最多 3 条记录 | `PluginDataResult.items` | 点击条目执行 `clickAction` 或首个 `navigate` |
| `quick_actions` | 标题 + 1–2 个按钮 | 不需要数据源；使用 manifest `quickCreate` / 页面入口 | 打开编辑页或插件页 |

### 3.4 数据与动作

- 复用现有 `PluginDataResult`，不新增第二套数据协议。
- 数据请求增加 `surface` 标识：`PAGE`、`HOME_WIDGET`（后续可加 `OS_WIDGET`），便于数据源区分场景。
- 宿主通过现有能力代理加载数据；插件未启用或未授权时，小组件不展示。
- 小组件动作 v1 只允许 `navigate`，不支持直接执行破坏性 host action。
- `quick_actions` 只使用 `quickCreate` 和 `entryPage`，不新增动作类型。
- 宿主路由需要支持带参数的起始页：`pageStartId + pageStartParams`，例如打开任务列表并带上 `filter=today`。

### 3.5 生命周期与刷新

| 场景 | 行为 |
|---|---|
| 插件启用 | 小组件进入“可添加”列表；默认按 priority 选前 3 个 |
| 插件禁用/隔离 | 小组件立即隐藏；保留用户偏好 |
| 插件卸载 | 小组件隐藏；数据按现有卸载策略保留或删除 |
| 重新启用/重装 | 恢复用户之前的显示与排序 |
| 主页恢复 | 并行刷新可见小组件；骨架 + 超时 + 失败重试 |
| 插件动作完成 | 刷新该插件的小组件；其他插件不受影响 |
| 备份导入 | 刷新全部小组件 |
| v1 后台刷新 | 不做；后续桌面小组件再用 WorkManager |

### 3.6 个性化与隐私

- 默认展示 priority 最高的 3 个小组件；其余进入“添加小组件”。
- 阶段 3 提供编辑入口：长按小组件或主页“编辑”按钮；编辑面板支持显示/隐藏、上移/下移、恢复默认。
- 偏好持久化在宿主（DataStore/SharedPreferences，沿用现有实现），按 `pluginId + widgetId` 保存。
- `sensitive: true` 的小组件支持“隐藏金额”；显示为 `••••`，点击后可在插件页查看。
- 桌面小组件后续复用同一 `sensitive` 标记，并考虑锁屏可见性。

### 3.7 版本与降级

- `homeWidgets` 为可选字段，向后兼容；不提升 `pluginSdkVersion` 主版本。
- 运行时遇到未知 `type`：忽略该小组件，不影响插件启用与主页其他内容。
- `dev-harness` 对第一方插件严格校验；未知类型给出 warning。
- 数据源缺失或返回失败：展示“无法加载 + 重试”卡片，不阻塞主页。
- 小组件 schema 文档独立为 `docs/home-widget-schema-v1.md`，避免与页面 schema 混在一起。

### 3.8 与桌面小组件的关系

- 复用同一份 `homeWidgets` 描述，增加 `surfaces`（后续）：`in_app`、`os`。
- OS 小组件只支持宿主模板（`summary`、`progress`、`quick_actions`），不支持插件自定义布局。
- 数据刷新通过 WorkManager 低频执行；不做实时推送。
- 第三方插件仍受执行模型限制，不能直接提供任意 RemoteViews/Compose。

- 每次只合并一个可验证的增量，避免主页与插件同时大改。

## 8. 风险与应对

| 风险 | 应对 |
|---|---|
| 小组件契约膨胀成第二套 UI schema | v1 只做 4 个模板；不支持嵌套、表单、长列表 |
| 主页数据加载慢 | 并行加载、单插件超时、骨架、内存缓存、失败重试 |
| 小组件过多导致主页臃肿 | 默认 3 个、总数上限 6 个、用户可编辑 |
| 新增插件仍要改宿主 | 代码评审禁止 `HomeScreen` 出现 `when (pluginId)`；新增插件只改 manifest + handler |
| 第三方插件预期落空 | 文档明确 v1 仅第一方；外部插件先解决沙箱执行模型 |
| 未知类型导致插件不可用 | 运行时忽略未知 type；`dev-harness` 仅 warning，不拒绝整个插件 |
| 小组件显示敏感金额 | `sensitive` + 隐藏金额开关；桌面小组件后续单独评估锁屏 |
| 现有交互回归 | 每个阶段跑完整测试 + 真机清单；保留撤销/空态验收 |
