# 隐私、数据与能力说明

LifeHub 是本地优先的生活工具聚合应用。首版不接入账号、云同步、广告或第三方统计 SDK，也不申请网络权限。

## 1. 本地保存的数据

| 数据 | 位置 | 用途 |
|---|---|---|
| 记账记录 | 插件私有 SQLite（按 pluginId 隔离） | 收支记录、分类、备注、日期 |
| 任务清单 | 插件私有 SQLite（按 pluginId 隔离） | 标题、说明、截止日期、优先级、倍率、完成状态、置顶状态；回收站数据保留 30 天 |
| 旅行足迹 | 插件私有 SQLite（按 pluginId 隔离） | 点亮的省/市/区县、地区评分（1–5 星）、每次评论的文字与时间；行政区边界随 APK 内置 |
| 插件状态 | SharedPreferences | 启用/停用/卸载、底部导航偏好 |
| 能力授权 | SharedPreferences | 记录用户同意过的能力 |
| 插件健康状态 | SharedPreferences | 连续异常计数与自动隔离标记 |
| 备份文件 | 用户通过系统文件选择器指定 | 口令加密后的离线备份 |

插件数据不能跨插件读取；宿主通过能力代理和插件私有数据库隔离访问。

## 2. 能力与用户同意

首版只开放两项能力：

- `ui.action`：执行插件页面上的动作与数据读取请求。
- `storage.private`：读写该插件自己的私有存储。

启用插件前，宿主会展示能力清单和插件声明的用途，用户确认后才授权。禁用、卸载或自动隔离会撤销授权；新增能力必须重新征得同意。

## 3. 日志与崩溃信息

- 应用统一使用 `AppLog`，只记录事件名、插件 ID、错误码和异常堆栈。
- 不记录记账金额、备注正文、任务内容、用户输入或备份口令。
- 首版未集成任何崩溃上报或分析 SDK；日志仅通过 Android Logcat 在本机可见。
- 如后续接入崩溃上报，必须在上报前移除插件数据正文，并更新本说明。

## 4. 备份与设备迁移

- 备份由用户主动导出，使用 AES-256-GCM 加密，密钥由用户口令派生。
- 口令只存在于内存，不写入 Keystore、文件或日志；丢失口令无法恢复备份。
- 系统自动备份已关闭（`allowBackup=false`，并排除 root/file/database/sharedpref/external），避免绕过加密备份把插件数据上传到云端或迁移到其他设备。
- 导入前会校验格式、校验和与数据版本，并展示覆盖预览；失败不会覆盖现有数据。

## 5. 删除数据

- **停用**：插件不可打开，数据保留，能力撤销。
- **卸载**：移除插件入口，数据保留，可重新安装。
- **永久删除插件数据**：独立操作，展示插件名、数据范围与不可恢复警告，二次确认后删除该插件的全部本地记录。
- **清除应用数据/卸载应用**：由 Android 系统删除应用私有目录中的全部数据。
- 备份文件由用户自行保管；删除应用内数据不会删除用户已经导出的备份文件。

## 6. 网络与第三方

- 首版 `AndroidManifest.xml` 未声明 `INTERNET` 权限。
- 未集成广告、统计、推送、账号或云服务 SDK。
- 插件均随 APK 内置，不从网络下载或执行第三方代码。
- 用户主动选择“导出高清地图”时，图片会写入系统相册的 `Pictures/LifeHub` 目录（Android 10+ 通过 MediaStore，无需存储权限；旧系统写入应用专属图片目录），不经过任何网络。
- 旅迹的省/市/区县边界在构建前离线预处理并随 APK 内置，运行时不访问 DataV、OpenStreetMap 或任何网络服务；没有区县的直筒子市与省直辖县级单位使用 OpenStreetMap 的乡镇街道边界（© OpenStreetMap contributors，ODbL）。
- 旅迹从 v1/v2 升级到 v3 时，旧备注只在本地转为评论、v2 随评评分聚合为地区评分，不上传、不合并到任何外部服务。

## 7. 用户控制

用户可以在插件主页启用、停用、卸载插件；在插件详情查看能力授权状态；在“备份与恢复”中主动导出或导入数据；在插件详情中永久删除某个插件的数据。

## 8. 变更方式

数据范围、能力、日志或第三方 SDK 发生变化时，必须同步更新本说明，并在发布检查表中记录审查结果。
